1. Project Overview

SecureDelete Simulator is a single-file educational desktop application that teaches users about data sanitization, secure deletion standards, and the limitations of software-level overwriting on SSDs — all without touching, deleting, or modifying any file on the user's system.

Safety guarantee: The application is read-only with respect to the selected file. It reads only filesystem metadata (name, size, modification time). No bytes are written to the selected file under any circumstances. Every simulated operation is clearly labelled [SIMULATED] in the activity log and the exported report.

3. Objectives

  • Demonstrate the step-by-step workflow of a real secure-deletion tool in a safe, read-only simulation.
  • Educate users on the difference between ordinary deletion and data sanitization.
  • Explain why multi-pass overwriting is unreliable on SSDs due to wear-levelling and over-provisioning.
  • Allow users to inspect file metadata without exposing file contents.
  • Generate and export a detailed plain-text educational report.
  • Handle all edge cases gracefully: missing files, empty files, permission errors, long paths.

4. Application Structure

_human_size()
Converts raw byte count to human-readable string (B / KB / MB / GB / TB). Handles 0-byte (empty) files explicitly.
_safe_stat()
Reads file size and modification time without raising. Returns (-1, "—") on any OS error — the central safety helper.
build_simulation_steps()
Returns an ordered list of log-entry dicts describing what a real secure-delete tool would do. Pure computation — zero disk writes.
build_report()
Assembles a full plain-text educational report combining file metadata, the simulated activity log, and the educational notes section.
SecureDeleteApp
Main tk.Tk subclass. Owns the 4-tab notebook UI, all state variables, the background simulation thread, and report export.
PASS_DEFINITIONS
Data-only list of the three simulated overwrite passes (zero-fill, one-fill, random). Weights are consistently typed as float.

5. User Interface — Four Tabs

① Simulator tab
  • Browse… — opens a file dialog; only filesystem metadata is read.
  • File Information card — shows Name, Extension, Size, Location, Last Modified, Status.
  • Simulation notice — inline amber warning above the buttons.
  • Simulate Secure Deletion — runs the animated log in a background thread (UI stays responsive).
  • Export Report — saves a .txt file; available before or after simulation.
  • Progress bar — advances step-by-step as simulation runs.
  • Activity log — colour-coded, scrollable, labelled [SIMULATED — no real operations performed].
② Educational Notes tab

Full-text educational article covering:

  • Ordinary deletion — how the OS simply removes the directory pointer.
  • Secure deletion on HDDs — DoD 5220.22-M, Gutmann, NIST SP 800-88.
  • SSD / flash limitations — wear-levelling, over-provisioning, TRIM, compressed writes.
  • Recommended SSD approaches — ATA Secure Erase, NVMe Format, encryption-based erasure.
③ Report tab

Live preview of the full plain-text report; updates whenever a file is loaded or a simulation completes. A "Save Report…" button exports to a .txt file.

④ How to Run tab

Built-in help page with requirements, run commands for Windows / macOS / Linux, a step-by-step walkthrough, edge-case documentation, and the safety disclaimer — all readable without leaving the app.

6. Simulated Deletion Workflow

When the user clicks Simulate Secure Deletion, the following sequence is logged (all steps are purely computational):

#StepDescription
1File info headerTarget name, size, path, drive anchor logged to the activity pane.
2Pass 1/3 — Zero-fill[SIMULATED] Overwrite every byte with 0x00. Sector and chunk counts derived from file size.
3Pass 2/3 — One-fill[SIMULATED] Overwrite every byte with 0xFF.
4Pass 3/3 — Random[SIMULATED] Overwrite every byte with cryptographically random data (PRNG).
5Verification read-back[SIMULATED] Each sector read back and compared to expected final pattern.
6Directory-entry removal[SIMULATED] Inode / directory entry marked free in the filesystem.
7MFT / FAT zeroing[SIMULATED] File-system metadata entry overwritten.
8Completion noticeDisclaimer that no actual operation was performed is printed in amber.

8. Edge Case Handling

Edge CaseBehaviour
No file selected Simulate button is disabled; clicking Export shows a descriptive warning dialog.
File deleted after selection Re-checked immediately before simulation starts. Status field set to "✗ File not found"; single ERROR log entry; no crash.
Empty file (0 bytes) Detected on load; Status shows "⚠ Empty file (0 bytes)"; amber NOTE entry in activity log; simulation continues normally.
Path longer than 90 chars Display label truncated with leading "…"; full path preserved internally for the report.
Permission error on stat() _safe_stat() catches it; metadata fields show "—"; simulation shows ERROR entry.
Permission error on export Separate PermissionError catch with a "choose a different location" dialog.
Non-file path selected Checked with path.is_file(); "Not a File" error dialog shown.
